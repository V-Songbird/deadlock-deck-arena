# Spanish/English text layer (`src/i18n.js`)

Investigated: adding an English translation to a build whose player-facing text is written
in Spanish inside the code, drawn entirely on a 640×360 canvas with a 5×8 pixel font, with
no gameplay, layout or architecture change allowed. Date: 2026-09-16.

## What was built

`src/i18n.js`, loaded in `index.html` **before** `src/core.js` because `DD.SLOT_NAME` is
player-facing text created at load time. It exposes:

```js
DD.i18n.lang()          // -> 'es' | 'en'
DD.i18n.t(s, ...args)   // also DD.t: exact Spanish string in, active language out
DD.i18n.set('en')       // stores localStorage['dd-lang'], then reloads
```

- **Key = the exact Spanish string as written in the code.** An unknown key passes through
  unchanged, so Spanish needs no entries and words that are identical in both languages
  (`'Torso'`, `'Torsos'`, `'Vulnerable {0}'`) need none either.
- **Placeholders `{0}`, `{1}`…** Every string that carried a number or a name was rewritten
  from concatenation into a template, so the *template* is translated and no value is lost:
  `DD.log('Recoges ' + n + ' de Ichor')` → `DD.log(DD.t('Recoges {0} de Ichor', n))`.
  Variants that Spanish built with a ternary became separate templates
  (`'{0} te debilita {1} turno.'` / `'{0} te debilita {1} turnos.'`).
- **Resolution at load:** `?lang=` in the URL → `localStorage['dd-lang']` → `'es'`. No
  navigator sniffing, so a bare URL with empty storage is byte-for-byte the shipped
  Spanish build. `document.documentElement.lang` and `document.title` are set at load.
- **`set()` rewrites an existing `?lang=`** instead of only reloading, because the URL
  outranks storage and the click would otherwise bounce back to the language just left.
  Verified live: `?lang=en&x=1` → `?lang=es&x=1` (the unrelated parameter survives).
- **Storage access is wrapped in try/catch** — `file://` and private windows throw, and the
  language is a bonus, never a crash.

`src/core.js` line 3 changed from `window.DD = {` to `window.DD = Object.assign(window.DD, {`
so core.js merges into the namespace i18n.js created instead of replacing it. That is the
only structural edit in the whole change.

`src/data.js` translates the roster inside its own `C`/`L`/`E` table helpers (three edits
covering 59 cards, 24 limbs and 7 enemies), so every consumer of `limb.name`, `card.desc`,
`enemy.name` etc. reads the active language with no call-site change. Ids are untouched, so
sprite lookup and the `deadlockdeck.v1` save are unaffected.

## Language control

A small `ui.button` on the title screen at logical `(466, 4, 52, 16)`, `{ small: true }`,
immediately left of the existing sound toggle at `(524, 4, 110, 16)`. Its label is the
language it switches to (`English` / `Español`, 7 chars = 41 px inside a 52 px button).
There is no pause screen in this build; the title screen is reached before a run and after
one through the `Título` / `Title` button on the death and escape screens.

## Width audit (why the English wordings are what they are)

`DD.ui.textWidth(s, size) === (s.length * 6 - 1) * size` and
`DD.ui.wrap` fits `floor((maxWidth + size) / (6 * size))` characters per line
(`src/render.js:106-127`). Every box was measured before wording:

| box | call site | budget | note |
|-----|-----------|--------|------|
| card name | `render.js:257` | `wrap(name, 64)` → 10 chars/line, **`.slice(0, 2)`** | a 3rd line is silently dropped |
| card description | `render.js:261` | `wrap(desc, 66)` → 11 chars/line, `.slice(0, 5)` | |
| codex grid cell | `screens.js:192` | `maxWidth 78` → 13 chars/line, 2 lines in 24 px | |
| dissection limb row | `screens.js:99` | x 452 → panel edge 630 = 178 px = 29 chars | with `(+N HP)` |
| dissection card list | `screens.js:100` | x 380 → 630 = 250 px = 41 chars, no wrap | 3 card names joined by `, ` |
| combat limb label | `render.js:291-296` | slot name 68 px (11 chars); limb name 135 px (22 chars) to the log at x 292 | |
| combat enemy name | `combat.js:243` | size 2 centred on x 500 → ≤ 23 chars before the 640 edge | |
| combat log | `combat.js:254` | `maxWidth 136` → **22 chars/line**, ~15 lines before the hand at y 262 | tightest box in the game |
| explore log | `explore.js:155` | `maxWidth 336` → 56 chars/line | |
| "Cómo jugar" panel | `screens.js:56` | `maxWidth 290` → 48 chars/line, 11 lines to the panel edge | EN uses 8 |
| title buttons | `screens.js:58-60` | `w 160` → ≤ 13 chars keeps size 2 | `Reanimate` / `Plans` / `Cosmetics` |
| end-screen buttons | `screens.js:41-42` | `w 300` → ≤ 24 chars; `w 180` → ≤ 14 | `New dissection table` / `Title` |
| shop status | `screens.js:222` | `maxWidth 128` → 21 chars/line, 6 lines | |

A scratch audit re-implemented `textWidth`/`wrap` and ran every English card name, card
description, limb name, limb description, enemy name and slot label through those budgets:
**0 overflows**, and the how-to panel uses 8 of its 11 available lines. `Planos` was
translated as **Plans** rather than *Blueprints* purely to hold these widths
(`6 plans` keeps the shop button at font size 2 the way `6 planos` does).

## Verification

- `node --check` on all nine touched JS files: OK (`i18n.js`, `core.js`, `data.js`,
  `body.js`, `tower.js`, `explore.js`, `combat.js`, `render.js`, `screens.js`).
- Dictionary: **319 entries, 0 duplicate keys**. 133 distinct `DD.t('literal')` keys appear
  in the code; the 5 that have no entry are deliberate identities
  (`Torso`, `Torsos`, `Vulnerable {0}` — twice for `Torso`, in `core.js` and `combat.js`).
- Loading `i18n + core + sprites + data + tower` under node stubs with `?lang=en`:
  **0 of the 24 limb names, 24 limb descriptions, 59 card names, 55 card descriptions,
  7 enemy names, 7 enemy descriptions, 4 trap names, 4 trap descriptions, 4 palette names,
  3 floor names and 6 slot names still read Spanish.**
- Grep for accented string literals outside `DD.t(...)` leaves only: the `HOWTO` array in
  `screens.js:16-20` (translated by `.map(line => DD.t(line))` on the next line), the
  `'English' / 'Español'` button labels (endonyms, deliberately untranslated), the font
  glyph keys in `sprites.js:1219-1232`, and `'Has muerto'` / `'El reloj se detuvo'` in
  `main.js:39,96,97` — those are dictionary **keys** passed to `die(why)` and translated at
  the point of use by `DD.t(reason).toUpperCase()` in `screens.js` (`death.draw`).
- Browser (Chromium pane, static server on :5199). `?lang=en`: title, dissection table,
  exploration, combat (cards, HUD, intent, stump label), harvest overlay, graft-slot list,
  death screen, codex grid, codex detail and shop all render in English with nothing
  clipped or overflowing. Tab title `Deadlock Deck: The Anatomical Clock`,
  `documentElement.lang = 'en'`. Clicking `Español` rewrote the query string, wrote
  `dd-lang=es` and reloaded into Spanish. With `dd-lang` removed and no query string the
  page renders the original Spanish (`SLOT_NAME.armL = 'Brazo izq.'`,
  `limbs.cabeza_reanimada.name = 'Cabeza Reanimada'`, `floorNames[0] = 'Sótano de Disección'`,
  `document.title = 'Deadlock Deck: El Reloj Anatómico'`). `read_console_messages`
  returned no output at any point.

## Known gaps

- `DD.data.enemies[*].desc` and `DD.data.traps[*].desc` are translated but are not drawn by
  any screen in this build; they were wrapped so the data layer stays consistent.
- The combat screen's limb-label column still overlaps the right edge of the player figure
  at scale 3. That is pre-existing (`render.js:287`, `bx = left + 22 * s + 4`) and is not
  worse in English, whose limb names are shorter than the Spanish ones.
